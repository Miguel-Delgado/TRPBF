# 🏆 Система организации турниров (TRPBF)

**TRPBF** — приложение для организации и управления турнирами. Проект позволяет создавать соревнования, регистрировать участников, формировать пары для матчей, фиксировать результаты и отслеживать победителей.

Проект разработан на Python. Изначально приложение представляло собой консольную программу с базой данных SQLite. В дальнейшем оно было расширено веб-интерфейсом на Django с использованием Django ORM, административной панели и пользовательских форм.

## 🏗 Архитектура

Проект развивался поэтапно: от консольного приложения с разделением ответственности до веб-приложения на Django.

### Консольная архитектура

Первоначальная версия построена с использованием нескольких логических слоёв:

```text
Пользователь
    |
    v
Консольный интерфейс (app.py)
    |
    v
Сервисный слой (services/)
    |
    v
Репозитории (repositories/)
    |
    v
Модели (models/)
    |
    v
База данных SQLite
```

**Назначение основных слоёв:**

- `models/` — описание сущностей предметной области.
- `repositories/` — операции чтения и записи данных.
- `services/` — бизнес-логика организации турниров.
- `app.py` — взаимодействие с пользователем через консоль.
- `database.py` — подключение к SQLite и инициализация базы данных.

### Django-архитектура

Для веб-версии используется Django. На ранних этапах веб-интерфейс работал с первоначальным слоем приложения, а после перехода на Django ORM работа с данными была адаптирована под Django-модели.

Основные компоненты веб-приложения:

- Django Apps — разделение функциональности по приложениям.
- Views — обработка HTTP-запросов.
- Templates — отображение страниц.
- Forms — получение и проверка пользовательских данных.
- Models — описание структуры данных через Django ORM.
- Admin — административное управление объектами.

## 📚 Предметная область

Основная задача приложения — автоматизировать проведение турниров.

Типовой процесс организации соревнования:

1. Создание турнира.
2. Регистрация участников.
3. Проведение жеребьёвки.
4. Формирование матчей.
5. Проведение соревнований.
6. Внесение результатов.
7. Подсчёт количества побед и определение лидеров.

### Особенность жеребьёвки

Если количество участников нечётное, одному участнику не находится пара. В таком случае используется механизм `bye` — технический проход в следующий этап.

В первоначальной SQLite-модели такая ситуация представлена матчем, у которого `player2_id = NULL`. Отдельный виртуальный участник для этого не создаётся.

## 🗄 Структура данных

В проекте используются четыре основные сущности:

| Модель | Основные поля | Назначение |
|---|---|---|
| `Tournament` | `id`, `name`, `status`, `created_at` | Информация о турнире |
| `Participant` | `id`, `tournament`, `name` | Участники турнира |
| `Match` | `id`, `tournament`, `round`, `player1`, `player2`, `is_played` | Матчи соревнований |
| `Result` | `id`, `match`, `winner`, `score`, `created_at` | Результаты матчей |

### Связи между моделями

- Один турнир может содержать нескольких участников.
- Один турнир может содержать несколько матчей.
- Матч связан с турниром и участниками.
- Результат относится к определённому матчу.
- Победитель результата связан с моделью участника.

Для существующих таблиц SQLite использованы имена через `db_table`, что позволило сохранить совместимость с уже имеющейся базой данных при переходе на Django ORM.

### Работа с базой данных

В проекте используется SQLite.

База данных хранится в файле:

```text
data/tournament.db
```

Для Django ORM структура моделей поддерживается с помощью миграций.

Это позволяет получать, фильтровать, сортировать и изменять данные без необходимости вручную писать SQL для каждой операции.

Зарегистрированы модели:

Для моделей настроены отображаемые поля, фильтрация и поиск.

| Форма | Назначение |

Некорректные данные не сохраняются в базе данных.

## ⚙ Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Miguel-Delgado/TRPBF.git
```

Перейдите в папку проекта:

```bash
cd TRPBF
```

### 2. Создание виртуального окружения

```bash
python -m venv venv
```

Активация в Windows:

```bash
venv\Scripts\activate
```

Активация в Linux/macOS:

```bash
source venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Запуск консольной версии

```bash
python main.py
```

Консольное приложение позволяет управлять турнирами через текстовое меню.

### 5. Запуск Django

При первом запуске Django-приложения выполните миграции:

```bash
python manage.py migrate
```

Затем запустите локальный сервер:

```bash
python manage.py runserver
```

Откройте в браузере:

```text
http://127.0.0.1:8000/
```

Административная панель доступна по адресу:

```text
http://127.0.0.1:8000/admin/
```

Для входа в административную панель необходима учётная запись администратора Django.

**Важно:** консольная и веб-версии являются двумя интерфейсами проекта. Консольную версию можно запускать отдельно от Django.
