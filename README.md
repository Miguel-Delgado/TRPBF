# Система организации турниров

**Автор:** Лапчинский Михаил Михайлович

## Назначение

Приложение автоматизирует организацию турниров: создание турнира,
регистрацию участников, жеребьёвку (формирование матчей первого тура),
внесение результатов и подсчёт зачёта. Проект разрабатывается как
индивидуальный и в перспективе будет расширен до веб-приложения на Django.

## Целевая аудитория

- Организаторы любительских и профессиональных соревнований (спорт,
  киберспорт, интеллектуальные игры).
- Администраторы мероприятий, которым нужна быстрая жеребьёвка.
- Участники, которые хотят заранее узнать своих соперников.

## Предметная область

Турнир – это соревнование, в котором участники встречаются друг с другом
по определённым правилам. Ключевые этапы:

1. Регистрация участников.
2. Жеребьёвка (формирование матчей).
3. Проведение матчей.
4. Фиксация результатов.
5. Определение победителя (зачёт по числу побед).

При нечётном количестве участников одному из них не находится пара — он
получает проход (bye) и техническую победу. В базе это отражено матчем с
пустым вторым игроком (`player2_id = NULL`), а не отдельным виртуальным
участником.

## Сущности предметной области

Каждая сущность описана отдельным классом в собственном файле. У модели есть
`__init__`, `to_dict()`, `from_row()`, `__str__`, а также метод
`create_table()`, который создаёт таблицу сущности и её индексы
(`CREATE TABLE IF NOT EXISTS ...`).

| Сущность | Файл | Атрибуты |
|----------|------|----------|
| Турнир (`Tournament`) | `models/tournament.py` | `id`, `name`, `status`, `created_at` |
| Участник (`Participant`) | `models/participant.py` | `id`, `tournament_id`, `name` |
| Матч (`Match`) | `models/match.py` | `id`, `tournament_id`, `round`, `player1_id`, `player2_id`, `is_played` |
| Результат (`Result`) | `models/result.py` | `id`, `match_id`, `winner_id`, `score`, `created_at` |

Полезные методы моделей:

- `Tournament.is_active()` — турнир ещё не завершён.
- `Match.is_bye` — одному из игроков не нашлось пары (проход).
- `Match.winner_id()` — победитель прохода.
- `Participant.to_dict()`, `Result.to_dict()` — представление в виде словаря.

## Схема базы данных

Хранилище — SQLite (`data/tournament.db`, создаётся автоматически при
первом запуске). Схема создаётся самими моделями через `init_db()`.

## Основные сущности 

- **Турнир** – словарь с ключами `name`, `participants`, `pairs`.
- **Участник** – словарь вида `{"id": 1, "name": "Иван"}`.
- **Пара** – словарь вида `{"player1": "Иван", "player2": "Петр"}`.

## Работа транзакций

Репозитории выполняют `commit()` после каждой операции записи, поэтому данные
сохраняются сразу. Удаление турнира каскадно удаляет его участников, матчи и
результаты (`ON DELETE CASCADE`); удаление участника обнуляет ссылки в матчах
и результатах (`ON DELETE SET NULL`).

## Обработка исключений

- `utils.input_int()` — перехват `ValueError` при нецелом вводе или числе
  меньше минимума, повторный запрос.
- `TournamentService.draw_matches()` — `ValueError`, если участников меньше
  двух.
- `TournamentService.record_result()` — `ValueError`, если матч не сохранён
  или указана недопустимая сторона победителя.
- `database.init_db()` — создаёт таблицы через `CREATE TABLE IF NOT EXISTS`,
  поэтому повторный запуск безопасен.
- `app.py` перехватывает `ValueError` сервиса и печатает понятное сообщение.

## Инструкция по запуску

1. Установите зависимости (нужны для тестов и проверки кода; для работы самого
   приложения зависимостей нет — используется стандартная библиотека):

   ```bash
   pip install -r requirements.txt
   ```

2. Запустите из корня проекта:

   ```bash
   python main.py
   ```

3. Работайте с меню: создайте турнир (1), добавьте участников (4), проведите
   жеребьёвку (6), внесите результаты (8) и посмотрите зачёт (9). Все данные
   сохраняются в `data/tournament.db`; при следующем запуске приложение
   автоматически подхватит последний турнир.

## Запуск тестов

Из командной строки **в корне проекта** (важно: команда `py`, а не `python` —
на Windows `python` может быть заглушкой Microsoft Store):

```bash
py -m pytest tests -v
```

Тесты используют базу данных в памяти (`:memory:`), поэтому не затрагивают
рабочий файл `data/tournament.db`. Не запускайте файлы из `tests/` напрямую
(кнопкой Run) — их выполняет pytest, иначе возможна ошибка `ModuleNotFoundError`.
